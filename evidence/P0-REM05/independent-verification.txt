D7 — BLOCKING, D1 residual: gate/task identity is not bound to the canonical
result path by the validator.

References:
- .harness/scripts/validate_phase1_graph.py:235-250 and 371-412
- .harness/scripts/validate_phase1_graph.py:425-433
- .harness/schemas/gate-results.schema.json:24-25

Evidence:
All 78 current paths are unique and correctly named, but an in-memory mutation
changes P1-TST01's write_result command from
`--gate AR02-G1.integrated-properties` to `--gate AR02-G1.schema` while retaining
`--output evidence/P1-TST01/AR02-G1.integrated-properties.json`. The validator
returns no errors. It checks the output path and command ordering, but never
checks that `--gate`/`--task` equal the path's gate/task. The schema accepts any
syntactically valid gate/task string and does not bind it to the file path.

Impact:
A schema-valid result can be written under the wrong canonical filename and
pass the planned lifecycle, so aggregators can consume mislabeled evidence.
The D1 lifecycle is not fully machine-checkable.
