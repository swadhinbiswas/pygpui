Defect list
-----------
D1 — BLOCKING, RT3-B01 residual: gate-result paths cannot represent the planned
results and staged aggregation overwrites evidence.
References: .harness/schemas/gate-results.schema.json:5-24; TASKS.json gate_evidence
and aggregate commands for P1-TST01, P1-PLAT02, P1-BENCH01, P1-LICENSE-CLOSE01 and
P1-PR-AUDIT01; validate_phase1_graph.py:235-242.
Evidence: schema type is object with one gate_id. Sixteen tasks have more than
one full gate/sub-gate but one gate_evidence file. Eight aggregate commands list
their output among their inputs. P1-PR-AUDIT01 writes AR09-G1 and AR10-G3 to the
same output. All 13 schema validations precede aggregation; CERT-GATE01 and
WAYLAND-GATE01 have no earlier command producing the validated file.
Impact: sequential execution either destroys a required sub-gate/full-gate record
or cannot encode multiple schema-valid results, so the staged model is not
runtime-executable as written.
Falsification: test_reproduces_eight_staged_aggregators_reading_and_writing_the_same_file;
test_reproduces_multiple_gate_results_sharing_one_schema_object_file;
test_reproduces_pr_audit_two_aggregates_writing_one_output;
test_reproduces_schema_validation_before_aggregate_output_exists;
test_validator_accepts_aggregate_self_overwrite.

D2 — BLOCKING, RT3-B02 residual: foundational code producers are unmerged control
tasks.
References: TASKS.json P1-SESSION-REGISTRY01 and P1-GATE-SCHEMA01;
validate_phase1_graph.py:226-228.
Evidence: both produce tools/ code (and the gate schema) but have workflow=control,
completion_state=recorded, no merge_task and no postmerge_command. Build consumers
depend on them. The validator explicitly accepts recorded control completion.
Impact: a dispatcher can treat locally recorded, unreviewed tool/schema code as a
satisfied dependency and branch from main without that code being merged.
Falsification: test_reproduces_unmerged_control_tasks_producing_code;
test_validator_accepts_control_code_producer_without_merge.

D3 — BLOCKING, RT3-B03 residual: AR09-G1/AR10-G3 do not aggregate per-PR
enforcement evidence.
References: TASKS.json P1-PR-AUDIT01 acceptance_criteria and gate_model entries for
AR09-G1/AR10-G3; phase-0-targeted-remediation.md:25; Phase 1 plan lines 302/309.
Evidence: each gate requires only <gate>.repository-evidence, and each aggregate
input list contains only evidence/P1-LIC01/gate-results.json. The only enforcement
command is pr_audit_gate.py --self-test. Removing both policy-test and
pr_audit_gate.py commands still validates.
Impact: the full gates can pass without staged evidence that per-PR provenance and
authored-scope enforcement actually ran.
Falsification: test_reproduces_repository_gates_without_enforcement_evidence;
test_validator_accepts_repository_gate_without_any_enforcement_command.

D4 — BLOCKING, RT3-B04 residual: durable license consumers still audit an
unpopulated ignored directory.
References: TASKS.json P1-LIC02 acceptance_criteria:3698-3704 and
P1-LICENSE-CLOSE01 acceptance_criteria:3894-3898; .gitignore:9.
Evidence: LIC02 audits dist/release/** at criterion index 0, then fetches at index
5 into evidence/P1-LIC02/downloads. LICENSE-CLOSE01 audits at index 1, then fetches
at index 4 into evidence/P1-LICENSE-CLOSE01/downloads. No command copies or audits
the downloaded files, and no later command repopulates dist/release.
Impact: in the declared fresh-worktree model, both tasks fail before the durable
fetch/verify can help.
Falsification: test_reproduces_license_audits_before_fetch_and_against_unpopulated_dist.

D5 — BLOCKING, RT3-B04 residual: ignored-artifact consumer detection is not

Falsification: test_validator_accepts_ignored_dist_consumer_with_wildcard_spelling.

D6 — BLOCKING, RT3-B01 residual: user-approval evidence is not bound to a real
